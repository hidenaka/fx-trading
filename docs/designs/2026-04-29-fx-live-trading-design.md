# FX自動売買ライブ取引システム Design

## Goal

既存のバックテストフレームワークを拡張し、OANDA REST API v20と連携してデモ口座で実際の自動売買を実行できるライブ取引システムを構築する。

## Architecture

既存のバックテストフレームワークに実行モード切替機能を追加し、OANDA REST API v20と連携して実際の注文を実行する。定期実行スクリプト（ポーリング）が「データ取得→シグナル生成→ポジション確認→注文判定→発注」を1サイクル実行する。デモ口座で動作検証後、設定変更のみでライブ口座に切り替え可能。

## Components

- `src/broker/oanda_client.py`: OANDA REST API連携。認証、価格取得、注文発注、ポジション確認を担当する。
- `src/broker/order_builder.py`: シグナルからOANDA注文JSONを構築（市場注文＋損切り＋利確）。
- `src/engine/live_engine.py`: `BacktestEngine`を拡張。`mode="backtest"`または`mode="live"`で動作を切り替える。
- `src/runner/polling_runner.py`: 定期実行のエントリーポイント。1サイクル分の処理を実行する。
- `src/config/settings.py`: APIトークン、アカウントID、取引設定（通貨ペア、時間足、リスク設定）を管理する。
- `src/monitoring/logger.py`: 取引ログ、エラーログ、パフォーマンスログをファイルに出力する。
- `src/safety/circuit_breaker.py`: 日次損失上限、取引時間外停止、緊急停止スイッチを提供する。

## Data Flow

```
[polling_runner.py起動]
    ↓
[OANDAから現在価格・ポジション取得]
    ↓
[データ前処理 → シグナル生成]
    ↓
[ポジション有無で分岐]
    ├── ポジションなし → エントリーシグナル確認 → あれば注文発注
    └── ポジションあり → イグジット条件確認 → あれば決済注文
    ↓
[結果をログ出力]
    ↓
[終了（次回の定期実行を待つ）]
```

## Error Handling

| 失敗モード | 対応 |
|-----------|------|
| API認証失敗（トークン期限切れ、無効） | 即座に終了。ログに記録。再実行は手動確認後 |
| ネットワーク接続失敗 | 3回リトライ（指数バックオフ）。それでも失敗なら終了 |
| 注文拒否（証拠金不足、無効な価格） | ログに記録。ポジションサイズ縮小を試行。それでも失敗ならスキップ |
| 重複エントリー防止 | ポジション確認APIで既存ポジションを常に確認。ダブルエントリーは物理的に防止 |
| クローズ失敗（決済注文が通らない） | リトライ。それでも失敗ならアラート出力。手動クローズを促す |
| 日次損失上限到達 | `circuit_breaker.py` が検知。当日の取引を自動停止 |
| 予期しない例外 | 全例外をキャッチ。ログ出力後に安全に終了。次回の定期実行に委ねる |
| レート制限（API呼び出し過多） | 429応答を検知。指定の待機時間後にリトライ |

## Testing Strategy

- **ユニットテスト**: OANDA APIクライアントの各メソッドをモックで検証（認証、価格取得、注文発注、ポジション確認）
- **統合テスト（モックサーバー）**: `responses` ライブラリでOANDA APIの応答をモックし、エンドツーエンドの注文フローを検証
- **設定検証テスト**: `settings.py` の必須項目（APIトークン、アカウントID）が欠損時に適切にエラーを出すか
- **サーキットブレーカーテスト**: 日次損失上限、取引時間外の動作を検証
- **セーフティテスト**: デモモードで誤ってライブ注文が出ないか（設定値の検証）

## 前提条件

- **ブローカー**: OANDA
- **口座タイプ**: デモ口座（初期）
- **動作方式**: 定期実行（ポーリング）
- **対象通貨ペア**: USD/JPY（初期）
- **時間足**: 1時間足（H1）

## セーフティ要件

- デフォルトは `practice`（デモ）環境。`live`環境への切り替えは明示的な設定変更が必要
- APIトークンは環境変数または `.env` ファイルから読み込み、コードにハードコードしない
- 日次損失上限を設定（例：資金の5%）。到達時は自動停止
- 取引可能時間帯を設定（例：月曜7:00〜土曜6:00 JST）。時間外は注文しない
- 1回の注文あたりの最大ロット数を制限
